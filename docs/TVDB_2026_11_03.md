# Lot TVDB — 3 novembre 2026

## Constat et contrats

Le fournisseur TVDB n'existait pas au constat initial de la mission. À la reprise,
le commit utilisateur `7e5b13c` contenait déjà le crate et cinq tests natifs ;
il est conservé. Ce complément termine ses raccordements de fabrication et ses
vérifications ciblées. Il ne réattribue pas les modifications préexistantes du SDK,
des collections, d'OpenSubtitles ou des autres fournisseurs.

`Aether-Plugins-TVDB` utilise les opérations métadonnées existantes. Le
[README](../Aether-Plugins-TVDB/README.md) précise configuration, identités,
langue/replis, limites épisodes, images et licence. Pas de modification du SDK
épinglé `133896830c609a177e4c4c611084154d7e4aab5d`, ni d'ABI ou de schéma Core.

Compléments : `scripts/test-tvdb-wasm.cjs`, liste des modules Wasm, cohérence
manifeste/catalogue, plan de release et choix manuels dans le workflow de
préparation. Le même oubli de sélection de release est réparé pour OpenSubtitles.
Les paquets signés existants et le catalogue publié restent intacts.

Deux corrections bornées du fournisseur : ne pas présenter le nom de base comme
un titre original de langue prouvée ; borner les résultats de recherche à 60 Kio
même avec des résumés Unicode longs. Un avertissement Clippy sur les crédits
est corrigé. Aucun ajout visuel ni nouvelle route Core.

## Limites, risque, retour arrière, suite

Aucun accès compte/licence réel, appel fournisseur externe, image importée via
un compte TVDB réel, PostgreSQL/NAS, CI Linux distante ou déploiement vérifié.
La protection des corrections manuelles/NFO et les permissions par bibliothèque
restent celles du pipeline Core existant ; les tests de ce lot vérifient le
contrat fournisseur, pas une nouvelle preuve du parcours d'application Core.
Épisodes sans identité exacte et token durable inter-invocations non implémentés.
Le harnais guest emploie WebAssembly de Node ; il ne mesure pas le fuel de
l'interpréteur Wasmi du Core sur des réponses réelles volumineuses.

Risques : évolution des réponses du service, licences d'accès, volume des détails
étendus et faible marge sous le plafond Wasm. Les réponses trop grandes échouent
explicitement plutôt que d'élever les limites du serveur. Retour arrière : désactiver
l'extension puis retirer ses seuls raccordements locaux ; aucune donnée média ni
migration à annuler. Prochaine priorité : validation sous licence autorisée puis
test Core signé/application et permissions, distinct du lot images de chapitres.
